# Project Intake

Use this reference when the user starts a project, asks for plan mode, says they want to modify a project, or gives a non-trivial product goal.

## Intake Fields

Record these fields in the project brief when they are known:

- Goal
- Audience or user
- Project size
- In scope
- Out of scope
- Acceptance standard
- Delivery target
- Forbidden actions
- Technical constraints
- Risk level
- Concurrency limit
- Assumptions

## Ask Only When Material

Ask only when the answer changes the plan, product result, safety boundary, staffing, or verification gate.

Do not ask just to fill a form. If the safe path is obvious, proceed and record a conservative assumption.

## Question Pool

- What is the expected project size: small fix, medium feature, large product, or long-running project?
- What outcome counts as accepted?
- What must stay out of scope?
- Are there forbidden actions such as publishing, deleting data, changing production config, or adding paid services?
- What is the maximum useful parallelism for this project?
- Are there quality bars such as tests, build, UI review, docs, security review, or release packaging?

## Recording Rule

The project lead thread records known answers and assumptions in the project brief. The coordination state records only current staffing and phase; it does not replace OpenSpec, tasks, or acceptance evidence.
